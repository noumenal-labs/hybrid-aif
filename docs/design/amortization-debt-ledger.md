# Amortization arc — debt ledger

*Status: LIVE list, opened 2026-08-27 at Alex's request during the
chunk-2b review. Every entry is complexity this arc introduced that a
razor-sharp principle would remove, with the principle named, the size
of the follow-up, and the gate that pays it. Entries are struck (not
deleted) when paid. The test of a good entry: a design doc could then
explain the mechanism without lying.*

**Why a dedicated list (Alex):** the package is complex enough and has
few users; if it is going to carry compositionality across module types
*and* arbitrary selection/ablation via a term grammar, the complexity
must be generated by principles a simple doc can state — otherwise
inconsistencies slow everyone down, coding agents included.

## The one principle most entries reduce to

**A term is a bucket; an estimator computes a leaf into it; the estimator
is dispatched by (term, variable family).** `infogain` already works this
way (V4: one term, four estimators by family). Every selector — today's
`epistemic=` and `terms=` — should be a spelling over that one dispatch.
Entries 1–3 are the three places 2b fell short of it.

## Entries

### 1. `epistemic=` is not literal sugar over `terms=` — two sibling selectors
- **What:** two registry tables (`ESTIMATORS` by `(kind, family)`;
  `ROWS` by name), two resolvers sharing only the suffix grammar. No
  `terms=` spelling reaches the four `infogain` estimators.
- **Principle violated:** one selector mechanism, `epistemic=` its
  restricted syntax (A11 pattern).
- **Follow-up:** register the `infogain` estimators as rows; teach the
  `terms=` resolver channel fan-out (`predictive` leaves key by
  observing modality), one-estimator-per-variable, the compiled path;
  make `epistemic=` a rewrite. (Family **eligibility** and the compiled
  carrier for rows landed with entry 2, so what is left is the keying
  and the within-term uniqueness rule.) Refactor of the v0.4 resolver under
  its parity suite. **Size: one chunk.** **Gate:** `register_estimator`'s
  first customer (brief `[deferred 2026-08-27]`; A12 item 1).
- **Landing site (2026-08-28):** both resolvers now live in
  `src/hybrid_aif/system/selectors.py`, side by side — the merge is a change
  within one file rather than across the old 3,280-line `system.py`
  (`system.md`, addendum "the `system` package").

### 4. G-side composition under `merge()` is a fence, not a design
- **What:** `merge()` raises on any component with `terms=`, a
  `preference_model`, a non-empty `scoring`, or a policy module in
  `policy_prior`. Vector E composes as before.
- **Principle needed (not yet stated):** whose critic scores a composite's
  joint policy? how do two components' `occupancy` leaves key without
  the row-name collision? `log_E` had a clean answer (sum over the joint
  policy set); modules and rows do not yet.
- **Follow-up:** an adjudication first, then the build. **Size: a design
  round + a chunk.** **Gate:** the first composite customer with an
  amortized component (the downstream mission executor is classical today).

### 7. Belief warrant is not tracked — rows hand-declare `derived`
- **What:** `Interval.derived` propagates by AND across *Intervals*. The
  beliefs a leaf is evaluated on are Distributions, not Intervals, so
  whether a derivation guarantees them (exact filtering vs. mean-field
  propagation through a net — a statement about enclosure, not about
  epistemic warrant in any wider sense) is invisible to the flag; every
  amortized row declares `derived=False` at registration.
- **Principle:** A4 said the flag would be widened, not un-designed. The
  next grade is a warrant on *beliefs* that the leaf AND-inherits.
- **Follow-up:** none scheduled; recorded so nobody reads the hand-set
  flags as mechanical. **Gate:** the first row whose own arithmetic is a
  derivation but whose inputs are not (the tabular `occupancy` row over
  amortized beliefs would be one).

### 9. `register_estimator` public API
- **What:** staged in `objective-terms.md` — open on the second customer.
  Listed because entry 1 is its remaining prerequisite: a user row must
  be able to reach the infogain machinery. Dispatch by family is now
  public-shaped (`register_row(..., families=...)`, entry 2), so the
  hook has one less thing to invent.

### 11. `q_pi` is a `Categorical` over a policy set — a continuous actor's distribution cannot be returned
- **What:** the planner protocol returns `(q_pi: Categorical, tree, policies)`.
  For a policy *module* under the habit planner, `q_pi` is a point mass on
  the one sampled plan; the actor's actual per-step distribution (mean/std)
  — the honest "why" of a habitual choice — has no return slot. CEM has the
  same shape problem (its proposal distribution is not a `Categorical`), and
  the gradient planner (b66e09c) is a third instance: `planning/gradient.py`
  returns a point mass on the optimised plan.
- **Principle:** the by-products of the selection computation should be
  returnable. Under `metrics=`'s rule ("return whatever the selection
  computed"), the term tree is the *model-side* channel (objective-terms.md:
  the tree scores the model, not the policy) — so policy-side by-products
  need a channel of their own, or the protocol's `q_pi` type widened to a
  `Distribution` over plans.
- **Follow-up:** none scheduled; pre-existing limitation surfaced by 2b's
  habit planner, not introduced by it. **Gate:** the first consumer that
  needs the actor's uncertainty at act time (a risk-aware executor; the
  distillation diagnostic gets by with `score_policies` on the plan).

### 12. A3's "E in every planner" is built for one planner
- **What:** A3 commits the E designation to all planners — enumeration
  (`q(π) = σ(ln E − γG)`, with a module's `E(π) = ∏_t π(a_t|s_t)` along each
  enumerated policy), CEM's `e_proposal=True` mode, and `habit`. 2b built
  `habit`; a module in `policy_prior` under enumeration raises at
  `planning/enumerate._prior_logits`, and CEM's `e_proposal` mode does not
  exist. Vector E under enumeration works as it always has.
- **Principle:** the search↔habit dial is *one formula* (A3) — search
  tempered by a learned habit is its middle setting, and the middle is what
  makes it a dial rather than a switch.
- **Follow-up:** evaluate the module inside the scoring scan (per-step
  beliefs are in the carry; the seam needs a second consumer of it); CEM's
  proposal initialized/tempered by the module. **Size: one small chunk.**
  **Gate:** the goal-(3) slider prods — the first experiment that wants the
  middle setting.

### 17. Ensemble members are a tuple of modules, looped in Python — DEFERRED 2026-09-29 (Alex)
- **What:** the disagreement rows' ensemble (`train/ensemble.py::ensemble_loss`,
  `objectives/amortized.py::_ensemble_disagreement`) holds its members as a
  tuple of modules and evaluates them in a Python loop, so each member is its
  own small matmul chain in the HLO, at every imagined step. Performance-review
  low (2026-09-29 pass).
- **Principle:** members with one shape are one batched module — a stacked
  leading axis on every parameter and `eqx.filter_vmap` over it.
- **Follow-up:** stack the members in `params.scoring` and vmap the loss and
  the leaf. The win is compile size and time (a few 2×32 members), not
  runtime; the cost is the params pytree, which reaches every kept checkpoint
  and the description's scoring-params format. **Gate: Alex's word** — do it
  when the stacked format is at least as tidy as the tuple (there are no
  external consumers to protect yet); decline if it is not.

## Paid

### ~~14. `init_learn_state` is not the whole-agent carry it claims to be~~ — PAID 2026-09-14 (adjudicated: a missing entry raises)
- **What:** `init_learn_state(params)` left `LearnState.moments` without the
  return-normalizer's entry; `imagine` added it on first call. A carry whose
  pytree structure changes mid-run cannot ride `lax.scan`, so the "one object
  to checkpoint" story held for Python loops but not scanned ones. Found by
  the 2d harness (chunk 2d note; worked around in `run_mc.scan_stable`, one
  line). Half-paid 2026-09-02 when divergence 13 gave `imagine` a second key
  and the seeder moved beside the keys (`train.imagine.init_moments()`),
  leaving only the layering half: whether `init_learn_state` should call it.
- **Principle:** the carry's structure is fixed at init — a face may fill a
  slot, never add one. The corollary that paid it: once the structure is
  fixed at init, a trainer handed a carry *without* its entry is looking at a
  dropped carry, not a first call, and a first-call backfill is a silent
  restart (divergence 29 is what that costs).
- **Paid (Alex, 2026-09-13: "this forgivingness burned us and we should make
  it raise"):** `init_learn_state` seeds `moments` through
  `objectives.amortized.scoring_moments(name)` — the `moments` half of
  `scoring_opt_state`, called from the same loop, so `system/` learns a row's
  running statistics exactly as it already learns its optimizer-carry shape,
  without importing `train/`. The keys live beside it and `train.imagine`
  re-exports them; `init_moments()` is gone. `imagine` no longer backfills: a
  supplied `LearnState` lacking either entry raises, naming the key and the
  fix (`learn_state=None` already raised, per A2). `run_mc.scan_stable` is
  deleted, its caller passes `init_learn_state`'s carry straight into the
  scan, and the structure check rides in
  `tests/test_amortized_trainers.py` (`tree_structure` before == after).

### ~~15. `MLPConditional` cannot express `norm: layer`, `tanh` means, or a σ ceiling~~ — PAID 2026-09-02
- **What:** the actor and the info-gain ensemble are `MLPConditional`s, and
  their resolved config asks all three of `norm: layer`,
  `actor_dist_cont: normal` with a `tanh` mean, and `minstd 0.1 / maxstd 1.0`.
  This family had no LayerNorm at all, an unbounded mean, and
  `1e-3 + softplus(raw)` with no ceiling. Its siblings
  (`MLPPredictor`/`MLPCategorical`) *do* carry LayerNorm, so this was a gap in
  one family rather than in the layer. Divergences 14 and 16 of
  `amortization.md`'s chunk-2d note, §(f).
- **Principle:** a declaration family should be able to express the
  architectures its slot is asked to hold; a capability that has to be
  simulated at the call site (here: `jnp.clip` standing in for a squashed
  mean) is a capability the declaration does not have. And the σ floor is not
  cosmetic on a sparse-reward task — `1e-3` permits an exploration collapse
  that `0.1` forbids.
- **Paid (adjudicated with divergences 14–17 as one build):** four
  `MLPConditional.from_shapes` options, every default **off** so an existing
  declaration is bit-identical: `norm=` (their `linear → LayerNorm(eps 1e-3) →
  act`, hidden biases dropped as theirs are), `head="bounded"` (their `Dist`
  'normal': `Normal(tanh(out), minstd + (maxstd−minstd)·σ(raw+2))` — with
  `minstd == maxstd` this is their `ig_head`'s fixed σ ≡ 1.0, gradient exactly
  zero), and `winit="normal"` (their trunc-normal fan-avg initializer, biases
  zeroed, the fused head layer drawn per half at fan_out = child_dim because
  theirs is two linears). The parity recipe (`reference/raif_agent.py`) opts in
  on the actor (`minstd 0.1 / maxstd 1.0`) and the ensemble
  (`minstd = maxstd = 1.0`); transcription tests against verbatim ports of
  their `MLP`/`Dist`/`Initializer` in `tests/test_oracle_transcription.py`.
  `winit` on the *other* families (encoder/decoder/critic/GRU — divergence 17's
  remainder) stays open in the chunk-2d coverage table.

### ~~16. The oracle's buffer alternation is inert, and ours is not~~ — PAID 2026-09-02 (adjudicated: match the code)
- **What:** at `train_ratio 64` their `should_train(step)` never returns ≥2, so
  `i` is always 0 and their `i % 2` branch **never** samples M⁺ — the oracle
  trained every gradient step on `M`. Ours alternated strictly, which is what
  A10 disposition 9, IDD §I and `raif_agent.train_step`'s docstring all said.
  Verified against `run/train.py:158-167`, `core/when.py:33-42` and
  `core/driver.py:70-72`; divergence 18 of the chunk-2d note, §(f).
- **Principle:** where the target's *code* and the target's *paper* disagree,
  the replication needs a recorded decision about which it replicates — and a
  signed-off decision is not silently replaced by a variant of itself.
- **Paid (Alex's ruling, 2026-09-02): parity = match the code, not the paper
  text.** `run_mc` / `raif_agent` default to world-model batches from **M
  only** (`Config.alternate = False`; the schedule is all-`False`); the
  `alternate()` API stays intact as the documented paper-described option (its
  API was separately adjudicated), and M⁺ keeps its live roles
  (`pref_label`/ρ CRSPP gating, success routing) unchanged. Alternation-ON is
  reserved as a labeled post-parity A/B: `run_mc --alternate`. Recorded at
  `amortization-p0-addendum.md` §7's FLAG-18 note.

### ~~2. `terms=` on a non-amortized System raises wholesale~~ + ~~8. Tabular/LG `occupancy` row~~ — PAID 2026-08-31
- **What (2):** a blanket check, not per-row eligibility. `occupancy` on
  a tabular transition is a *different estimator for the same term*
  (`E_q H[B(·|s,a)]`, closed-form, `derived=True`) that did not exist,
  so the resolver refused everything. **(8):** `objective-terms.md`
  placed that row; only the amortized estimator existed.
- **Principle:** rows dispatch by family like `infogain` does. The
  blanket raise was a placeholder for family dispatch of `terms=` rows.
- **Paid (the vignette-1 build, first customer = a MOP T-maze):** one
  row name, **two estimators keyed by family**. A
  `registry.Estimator` now declares `families`, `register_row` admits a
  second registration under an existing name only as a *disjoint-family
  variant* (agreeing on everything a consumer reads without knowing the
  family — term, keying, target, slot, parametric, needs_structure,
  terminal — so only `prepare`/`derived` may differ), and
  `row_variant(name, family)` is the dispatch. The tabular estimator is
  `registry._occupancy_transition` (+ a fused prob-space carrier over
  `CompiledTables.B_probs`), leaf
  `E_{q(parents)} H[B(child|parents,a)]` keyed `transition:<factor>`
  like its sibling, `derived=True`, mean table for a learnable
  declaration (D2). `_row_mounts` now computes a per-factor family
  (amortized structure, or `_hybrid.factor_families`) and refuses
  **per row and per family**; the blanket raise is gone. Both declared
  carriers (`compiled`, `hybrid`) take resolved `mounts`, and
  `reads_prev` on the row is what pulls in the `(qs, qs_prev)` planning
  carry that transition novelty already needed. Design:
  `objective-terms.md`'s 2026-08-31 build note; the grammar amendment
  is in `amortization.md`'s `terms=`-grammar note, section (a).
- **Left behind, deliberately:** entry 7's gate is now reachable (a
  `derived=True` row over amortized beliefs would be the case it
  describes) but nothing mounts that combination, so the warrant axis
  is unchanged.

### ~~5. CRSPP rollout starts from its declared episode start (2b)~~ — PAID 2026-08-28
- **What:** their `observe_no_action` conditions the CRSPP posterior on
  the actual observation sequence before imagining; a planner is handed
  beliefs, not observations, so 2b's cosine term compared the agent's
  rollout against a *generic* preferred trajectory. Diagnostics-only
  under the habit planner, so nothing acted on it — but not
  parity-faithful, and 2b cosine numbers are not comparable to theirs.
- **Principle:** a scoring row that owns a System may need that System's
  *beliefs* — per-tick carry, neither structure nor params. That is a
  third kind of row input, and it needs a seam (auxiliary beliefs passed
  per call), plus CRSPP recognition conditioned on the agent's embedding
  *as data* (never as a shared module — A11's pytree-forking commitment).
- **Paid (chunk 2c):** three mechanisms, each the smallest that does its
  job — (i) an **external-input parent kind** on `Recognition`
  (`parents=("deter", "external:embed")`, widths in a new static
  `System.external_inputs`, values supplied per call through
  `recognize(..., externals=...)` / `infer_states(..., externals=...)`);
  (ii) **auxiliary beliefs**, a third `Statics` field beside `scoring`
  and `declared`, narrowed per row by `_mount_statics` and reachable as
  `planner_context(..., aux_beliefs=...)` / `score_policies(...,
  aux_beliefs=...)`, with the cosine row falling back to its declared
  episode start when none is supplied; (iii) the producer in the
  trainer — `reference.crspp.observe_no_action` / `crspp_recognize`, threaded
  in by `imagine(..., aux_beliefs={row: beliefs})`, with the agent's encoder run
  on the agent's side (`train.world.embeddings`). `imagine` and the
  planners now share one closure builder (`System._amortized_scoring`),
  so there is still exactly one scoring path. Design:
  `amortization.md`'s "A12 implementation note: chunk 2c" (a). One
  divergence recorded there rather than fixed: the preferred trajectory
  is still rolled mean-field, because `predict_beliefs` is keyless.

### ~~6. Scoring-row rates and `LearnState` raise until 2c~~ — PAID 2026-08-28

- **Principle:** honoured, not violated — `learn` has no per-tick

  `ACTOR_KEY = "policy_prior"` — and each trainer steps its own subset
  and threads the rest through, which is what keeps A6's trainers
  à-la-carte. `LearnState` gains a second field, `moments`, for the
  return-normalizer's percentile EMAs (not optax state; nothing steps

### ~~3. CRSPP structure on a bespoke `System.preference_model` field~~ — PAID 2026-08-27
- **What:** a row that owns a whole System needs structure on `System`

  entry. **Size: small (one field, one row, its tests).** **Gate: Alex's
  word** (the build declined to guess a second customer's shape; the

- **Paid (chunk 2b, pre-commit):** `System.scoring: tuple[tuple[str, object], ...]` (static; tuple-of-pairs per the `subsystems` precedent) ↔ `SystemParams.scoring`. A mounted row that `needs_structure` and finds none raises; a structure entry `terms=` does not mount raises. `preference_model` is gone. +5 tests.
